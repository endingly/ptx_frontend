# Tensor asynchronous data movement

The frontend resolves tiled tensor-map forms in [PTX ISA 9.3 §5.5 and §9.7.9.26.5](https://docs.nvidia.com/cuda/archive/13.3.0/parallel-thread-execution/index.html). The composite `[tensorMap, {coords}]` keeps its nested address, coordinate elements, punctuation, and source ranges through CST and AST lowering. Resolved IR owns a `ResolvedTensorMapRef` and a rank 1–5 `ResolvedTensorOperand`. The 20 copy/prefetch variants and 40 reduction variants accept omitted or explicit `.tile`; the `tile` field records whether it was written.

The 27 no-offset store/reduction forms use the explicit fixed `.im2col_no_offs` mode. The generated binding carries a closed expected `TensorAccessMode`, and the owned tensor operand retains that mode after the syntax tree is destroyed. The original 60 tiled forms still have `Tiled`, including when `.tile` is omitted; non-tensor forms have no tensor mode. The selected no-offset form and owned mode preserve fixed qualifier identity, but there is no separate source location for that fixed token and no byte-for-byte source reconstruction claim. No `im2colInfo` operand is present for this mode.

The 27 im2col read identities use fixed `.im2col`, `.im2col::w`, or `.im2col::w::128` modes on ranks 3–5 across CTA load, cluster load, and L2 prefetch. Each has separate layouts with and without `im2colInfo`: omission remains explicit absence, with no invented zero vector or known execution default. A present `ResolvedTensorIm2colInfo` owns register or immediate elements, source ranges, and the enclosing brace-pack range after AST destruction. `tensor_im2col_info_role(tensor, info, index)` returns typed W/H/D-offset or halo/offset roles from the selected mode and rank, or no role for an inapplicable/malformed query. Plain `.im2col` uses one, two, or three W/H/D offsets at ranks 3, 4, or 5, bounded by 65535, 255, or 31 respectively. Both W modes use `{wHalo,wOffset}`: halo is at most 511 for `.im2col::w` and 31 for `::w::128`; offset is at most 31. Integer constants narrow to unsigned 16 bits at this operand use before those bounds; original 64-bit source bits and sign remain available. General scalar B16/U16/S16 register carriers are accepted, while their runtime values retain bound obligations.

The four gather/scatter identities are rank two with **five** ordered coordinates: one column index and four independent row indices. The generated binding carries expected tensor rank independently of coordinate cardinality. `tensor_gather_scatter_coordinate_role(tensor,index)` returns an owned `Column` or `Row0`–`Row3` value only for a valid mode, rank, count, and index. PTX 8.7 clarified the older four-x/one-y wording to `{x,y0,y1,y2,y3}`; the role API follows the instruction operand table without guessing descriptor dimension numbering. These fixed modes have no `im2colInfo`. Scatter rejects a converted-negative literal in any of the five positions, while gather reads may retain one. Scalar register contents, bounds, descriptor rank, four-row box construction, box dimension 1 equal to one, and non-interleaved layout remain runtime or opaque-descriptor obligations.

CTA gather starts at PTX 8.6 on catalog SM ≥100, including valid generic profiles. Cluster gather, gather prefetch, and scatter require exact `sm_100a` at 8.6, the `sm_100f` family at 8.8, or the `sm_110f` family at 9.0. Catalog inheritance includes `sm_103a/f` and `sm_110a/f` at their own floors; generic profiles and `sm_120` families do not satisfy those qualified forms. Gather loads reuse mbarrier complete-tx-bytes, prefetch has no completion operand, and scatter uses BulkGroup. CTA locality and remote cluster/barrier relationships remain obligations where pointer metadata cannot establish them.

Plain im2col cluster load and prefetch start at PTX 8.0 / SM 90; CTA load starts at PTX 8.6 / SM 90. W forms start at PTX 8.6. `.im2col::w` CTA load accepts catalog SM 100 or higher, including generic profiles. The cluster-load W qualifier permits exact `sm_100a` at 8.6, the `sm_100f` family from 8.8, or the `sm_110f` family from 9.0. The instruction-local target paragraph lists only the first two; PTX 9.3 Table 63 explicitly adds the `sm_110f` family for W cluster loads. W128 loads and either W prefetch use the same three exact/family clauses; family inheritance follows the target catalog. The W modes require descriptor swizzling and exclude the combination of 128-byte swizzle, 32-byte atomicity and 8-byte flip. Descriptor contents are opaque, so that restriction, filter/bounding-box compatibility, and the execution meaning of omitted info remain obligations rather than inferred static facts.

This frontend follows the pinned PTX 9.3 syntax and value bounds. In complete-module probes, ptxas 13.3.73 assembled all 27 present-info im2col read forms but rejected all 27 omitted-info forms with `Arguments mismatch`; the frontend retains omission because the formal syntax permits it. The assembler also accepted three tested values that exceed the frontend's post-U16-conversion bounds (plain rank 4 offset 256, `.im2col::w` halo 512, and `.im2col::w::128` halo 32). Its PTX 9.0 / `sm_110a` W cluster acceptance corroborates Table 63's `sm_110f` family clause; it is not a discrepancy with the whole pinned manual. Omitted-info execution behavior is unknown. These assembler outcomes do not establish GPU runtime validity, descriptor compatibility, or synchronization correctness.

A 77-module ptxas 13.3.73 gather/scatter corpus accepted all four canonical forms and all four tested example-order modifier spellings. Its target results corroborated the CTA numeric floor and the three qualified target cohorts. It rejected an unsigned-64-max coordinate literal in each form with `Arguments mismatch`, although the frontend preserves that legal integer source and narrows it to S32 at use. Conversely, it assembled a scatter coordinate whose converted S32 value is negative (`0xffffffff`); the frontend retains the manual's nonnegative tensor-write rule. PTX 8.9 is not an assembler-supported module version, so the corpus uses supported 8.8 and 9.0 endpoints around that floor. Assembly does not prove descriptor layout, bounds, synchronization, or GPU execution.

`tensorMap` is a generic pointer to an opaque 128-byte descriptor. A direct descriptor symbol may reside in kernel `.param`, `.const`, or `.global` storage; its declaration identity, storage space, alignment, and source range stay in owned IR. A register pointer retains its register identity, while its runtime storage and alignment remain unknown. Tensor data direction is modeled separately: load reads global tensor data into shared memory; store reads CTA shared memory and writes global tensor data.

The checker compares owned rank with the generated fixed rank independently of exact coordinate count. Earlier modes have one signed-32 coordinate per rank; gather/scatter uses five for rank two. Coordinates accept compatible scalar 32-bit registers. PTX 64-bit integer constants are converted to signed 32 bits at coordinate use, with the original source value and sign retained in owned IR: `4294967296` converts to zero, while `4294967295` converts to −1. Loads and prefetch may use negative converted coordinates. Stores, scatter and reductions reject statically negative converted coordinates; register coordinate values require runtime validation. Known descriptor, shared data, and mbarrier addresses must be aligned to 64, 16, and 8 bytes respectively. The shared-data check is the tiled mode baseline; stronger alignment required by the descriptor's swizzle mode remains a runtime obligation because the descriptor is opaque here. Unknown register-pointer alignment is not treated as proven. The checker rejects a known shared/local or non-kernel parameter descriptor and verifies PTX/SM availability.

For reduction, a generated `TensorReductionOp` identifies the fixed operation and `tensor_reduction_accepts_element_type` reports conditional descriptor compatibility. `add` accepts U32/S32/U64/F32/F16/BF16; `min` and `max` accept U32/S32/U64/S64/F16/BF16; `inc` and `dec` accept U32; bitwise `and`, `or`, and `xor` accept B32/B64. The query does not read descriptor contents, so its result cannot prove that an opaque descriptor has the queried type. Reduction retains bulk-group completion, with no mbarrier operand or byte accounting; descriptor content, operation/type agreement, swizzle, stride, bounds, and runtime ordering remain caller obligations. The PTX syntax and completion paragraph specify bulk-group here despite a conflicting mbarrier sentence in the descriptive prose.

All 73 tensor-write forms, 27 im2col reads, and three gather reads recheck owned scalar 32/64-bit integer/bit pointer carriers, including vector shape and known type. Gather/scatter also rechecks all five scalar coordinate carriers after AST destruction. Known map-read storage remains global/const/kernel input param with 64-byte alignment; known shared data and mbarrier addresses require 16 and 8 bytes respectively. Unknown pointer storage and alignment remain runtime obligations. Descriptor contents, rank consistency with descriptor bytes, swizzle, stride, bounds, barrier locality, and runtime synchronization cannot be proven from this slice. Multicast, explicit CTA group, and cache policies or hints remain outside this supported subset. Unsupported adjacent spellings fail selection.

## Tensor-map field replacement and proxy fence

The `tensormap.replace.tile` subset covers all 11 field names: `global_address`, `rank`, `box_dim`, `global_dim`, `global_stride`, `element_stride`, `elemtype`, `interleave_layout`, `swizzle_mode`, `swizzle_atomicity`, and `fill_mode`. The first six take a `.b32` or `.b64` register or integer literal as specified by the field; the last five take only an immediate Table 33 code. An optional `.global` or `.shared::cta` qualifier must agree with the known destination space. A replacement destination is a writable global or CTA-shared descriptor object, not a const or parameter descriptor. Address registers with known types must be 32- or 64-bit integer/bit registers; the same rule applies to proxy-fence source and destination addresses. The generated variant exposes `replacement_field`, an owned-copy `tensor_map_ref()` preserving address and source identity, and, for encoded fields, an optional field-specific `encoded_value()`. These projections do not decode the 128-byte descriptor.

`rank` encodes dimension count minus one. A register rank remains a runtime obligation; an immediate is converted to `.b32` at use and the resulting code must be 0–4. Other typed `.b32`/`.b64` replacement literals also narrow at use. The optional `ord` selector for dimension and stride fields must be an original-source integer in 0–4. Table 33 codes likewise require an exact original-source value: a multiple of 2³² is not an alias for code zero. The five closed value domains are element type (0–15), interleave layout (0–2), swizzle mode (0–4), swizzle atomicity (0–3), and fill mode (0–1). Element code 15 is one encoded identity whose meaning is `b6x16_p32` on tensor load and `b6p2x16` on tensor store. Source bits, converted bits, and original sign remain in owned IR; the checker revalidates consistency after mutation.

The basic replacement target catalog has six alternatives: exact `sm_90a` at PTX 8.3, exact `sm_100a` at 8.6, exact `sm_120a` at 8.7, the `sm_100f` family at 8.8, the `sm_110f` family at 9.0, and the `sm_120f` family at 8.8. The explicit source-target catalog supplies family inheritance; a generic target with the same numeric SM is insufficient. Swizzle atomicity requires PTX 8.6 and excludes `sm_90a`. Element codes 13–15 require PTX 8.7 and exclude `sm_90a`. Swizzle-mode code 4 (96 B) requires PTX 8.8 on exact `sm_103a`. The checker intersects these field/code gates with the basic target catalog. Compatibility with current descriptor contents and subsequent data access is conditional and remains a runtime obligation.

The `tensormap.cp_fenceproxy.global.shared::cta.tensormap::generic.release.{cta,cluster,gpu,sys}.sync.aligned [dst], [src], 128` form copies a CTA-shared tensor map to global storage and releases generic-proxy writes for subsequent tensor-map-proxy access. It starts at PTX 8.3 / SM 90, uses the existing `MemoryScope` and `TensormapToGeneric` pair, and has no asynchronous completion group. The fixed copy size is an original-source 128-byte immediate; owned validation checks that its converted `.u32` bits still equal 128. Replacement operates weakly on the entire 1024-bit descriptor; applying the natural access-size alignment rule yields 128-byte alignment for a known destination. Both known proxy-copy addresses also require 128-byte alignment. This is a manual-derived contract rather than an assembler-rejection claim. An unknown register address keeps its runtime alignment obligation. The earlier 64-byte tiled-read descriptor alignment is unchanged.
