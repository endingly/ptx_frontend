# PTX 9.3 `ldu` 覆盖范围

前端建模 PTX ISA 9.3 §9.7.9.10 中已文档化且受支持的形式。`ldu` 从 warp 内地址一致的
只读 global 数据加载。前端检查指令形式与地址来源；它不证明运行时地址一致，
也不证明数据在运行时只读。

| 形式 | 状态空间 | 目标 | 可用条件 |
| --- | --- | --- | --- |
| `ldu.type d, [a]` | 省略后缀时使用指向 global 数据的 generic 寻址 | 标量寄存器 | PTX 2.0 / SM 20 |
| `ldu.global.type d, [a]` | 显式 global | 标量寄存器 | PTX 2.0 |
| `ldu.v2/v4.type d, [a]` | 省略后缀时使用指向 global 数据的 generic 寻址 | 两个或四个寄存器 | PTX 2.0 / SM 20 |
| `ldu.global.v2/v4.type d, [a]` | 显式 global | 两个或四个寄存器 | PTX 2.0 |

标量形式支持 8、16、32、64 位的 `.b/.u/.s` 类型，以及 `.f32`、`.f64`
和 `.b128`。向量加载总宽度最多为 128 位：v2 支持不超过 64 位的元素
（包括 `.f64`），v4 支持不超过 32 位的元素；`.b128` 仅支持标量形式。
`.f64` 要求 SM 13；`.b128` 要求 PTX 8.3 与 SM 70。若类型的最低要求更低，
generic 寻址仍需满足其自身的最低要求。目标寄存器的每个
元素宽度必须不小于加载类型。检查器验证寄存器类型兼容性、向量元素个数、
对齐和已知地址的 global 来源。来源未知的地址寄存器可以表示指向 global 的
generic 指针。向量目标占位符 (`_`)、`.v8`、缓存控制符和 `.global` 以外的
状态空间不属于文档规定的前端契约。部分 `ptxas` 版本接受向量元素 `_`，但
PTX 9.3 未将其列为 `ldu` 的文档化形式。
